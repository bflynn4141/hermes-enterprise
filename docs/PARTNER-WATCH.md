# First proactive responsibility: GitHub partner watch

This is the first opt-in responsibility on the existing partner-screening skill.
The browser does not schedule or execute it. Cloudflare Cron admits durable
source checks; a material change can wake the agent's existing official Hermes
profile and prepare one private, cited deliverable in the owner's Inbox.

## Experience

- The agent owner chooses one already configured public GitHub organization
  source, cadence, and per-check and daily model spending limits.
- The first check saves a baseline without calling the model. Unchanged checks
  also stay quiet. Counter changes and fetch timestamps do not wake the model.
- A material change selects one candidate and freezes its evidence for a review.
  Repository activity is evidence of activity; it does not establish that a
  feature shipped, that a partner is qualified, or that outreach is appropriate.
- The result is an existing `deliverable` approval with cited source facts,
  uncertainty, and a useful next step. It has no outbound effect or dependent
  request release. The watch cannot send email, enrich contacts, grant access,
  sign, or make payments.
- Pause prevents new admissions and revokes subsequent model and tool calls.
  A provider request already in flight may finish and remains accounted for.
  Run now requires the watch to be enabled. Each deliberate click has a new
  occurrence key; retrying the same key cannot replenish source allowances.
  Overlapping scheduled and manual checks coalesce before another source call.
  An Admin-paused skill permits draft settings changes but requires an Admin
  to resume it.

The overview shows source, schedule, limits, last check, next check and the
latest result. A result link opens the existing Inbox. Configure is a short
dialog; a changed assignment revision must be reviewed before another save.

## Authority and accounting

The watch is opt-in configuration on the existing immutable skill assignment,
not a new tool grant or native-runtime pin. Each durable check captures the
active owner, assignment revision, source scope and allowances. The scheduler,
source handoff, model proxy, tool bridge and deliverable validator recheck the
current authority. A member cannot manage another owner's private watch.

Source requests use the existing bounded free GitHub connector. Model calls
reserve a conservative upper bound before reaching the provider, under a
serialized daily allowance. Verified catalog pricing is required. Actual
confirmed usage reconciles the reservation; uncertain usage keeps the bound
charged. Recovery keeps the original evidence and allowance rather than
creating a new responsibility or spending authorization.

For this first release the reservation uses the model's full catalog context
ceiling and at most 2,048 output tokens. A model whose conservative bound
exceeds the selected limit is refused rather than silently substituted. The
limit accounts for verified catalog model rates, not unverified provider fees.
Explicit Pause or settings changes cancel unfinished checks; their spending
remains in the daily ledger. A stranded source check can be cancelled with
Pause and then resumed; automatic replay does not reset its request allowance.

This does not allocate a VM per agent. It reuses the existing agent-bound
profile and ordinary admission, concurrency, workspace limits and attestation.
The present native-run window remains bounded; a multi-day browser session is
outside this milestone.

## Pilot activation and honest verification

A normal PR preview uses fake sign-in, a scripted model and no Cron. It can
verify interface behavior, but cannot demonstrate useful real model work while
the user is offline. Mock watch fixtures are explicitly labeled Sample.

For real acceptance, use one explicitly approved public GitHub source and the
owner's governed profile on an already authorized host. Verify the profile's
exact enterprise URL, workspace, agent identity, current skill attestation and
workspace inference access before enabling the responsibility. A profile bound
to staging cannot simply be copied into a preview. Preserve staging/production
release approvals and the owner's existing recurring spending authorization.

Record these observations for the first real pilot:

1. Baseline check stores real source artifacts without model inference.
2. A later real source change produces immutable before/after evidence.
3. Close the browser; the durable job and official Hermes run complete anyway.
4. Reopen the Inbox and inspect the review, citations, uncertainty and useful
   next step against the source. Record actual latency and accounted model cost.
5. Confirm a repeated trigger produces one review, an unchanged check is quiet,
   and Pause or loss of authority prevents further spending.

A recorded fixture, simulated model response or healthy runtime endpoint is
not evidence that this real pilot passed. No fleet should be provisioned before
the owner finds the first result useful.

## Visual direction and motion

[Paper component direction](https://app.paper.design/file/01M2B594V9R1KZKZ398A79KVHA/p-M-0)
extends the existing Hermes typography, colors and controls. It is a Sample
review-ready state, not a claim of a live run or working animation. Activity
indicators reflect recorded checking or model work; no artificial wait or
celebration. Existing Dialog/StatusDot primitives preserve reduced-motion
behavior. Review desktop and narrow rendering before release.
